What it checks

Four checks, each deterministic, each with a real reason it exists.

Volume overflow

Checks cumulative liquid added to a well, across every step, against that well's real container capacity.

Step ordering

Checks that nothing is drawn from, incubated, or measured before an earlier step has actually filled it.

Tip contamination

Runs the generated code for real, with aspirate and drop_tip instrumented, and flags a tip that touches two reagents before being replaced.

Verified code generation

Only generates real Opentrons Python for a plan that has already passed every check above, nothing is generated first and checked after.

How it works

Five stages. Only one of them touches an LLM; the rest are plain deterministic code, the same code this page just called.

Stage 1
Extractor
Reads English protocol text and turns it into structured steps: actions, volumes, sources, destinations.
LLM
Stage 2
Labware resolver
Matches each container to a real entry in the Opentrons catalog and reads its actual well capacities.
Deterministic
Stage 3
Checker
Checks cumulative volume against real capacity, source depletion, and physical step ordering.
Deterministic
Stage 4
Tip contamination check
Runs the generated code for real, with aspirate and drop_tip instrumented, to catch unsafe tip reuse.
Deterministic
Stage 5
Generator
Only runs on a plan that already passed every check above, and turns it into real Opentrons Flex Python.
Deterministic
