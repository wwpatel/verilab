Step ordering

Catch ordering errors

Nothing can be drawn from, incubated, or measured before an earlier step has actually filled it. Verilab checks the physical sequence, not just the syntax.

A well referenced before it's ever filled is a silent no-op on a real robot. The pipette draws air, and the mistake is invisible until someone checks the physical plate afterward.

Tip contamination

Catch tip contamination

Verilab runs the generated code for real, with aspirate and drop_tip instrumented, and flags a tip that touches two reagents before being replaced.

This check does not read the code, it runs it. Aspirate and drop_tip calls are instrumented during a real execution, so the finding is based on what the tip actually touched, not a guess from the source.

How it works

Five stages, one of them an LLM

The rest is plain deterministic code, the same code the sections above just showed you the real output of.

Stage 1
Extractor
Reads English protocol text and turns it into structured steps: actions, volumes, sources, destinations.
LLM
Stage 2
Labware resolver
Matches each container to a real entry in the Opentrons catalog and reads its actual well capacities.
Deterministic
Stage 3
Checker
Checks cumulative volume against real capacity, source depletion, and physical step ordering.
Deterministic
Stage 4
Tip contamination check
Runs the generated code for real, with aspirate and drop_tip instrumented, to catch unsafe tip reuse.
Deterministic
Stage 5
Generator
Only runs on a plan that already passed every check above, and turns it into real Opentrons Flex Python.
Deterministic
